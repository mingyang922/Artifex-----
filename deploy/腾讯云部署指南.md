# 腾讯云端部署指南

> 最后更新：2026 年 7 月 30 日
>
> 当前生产环境：`https://artifex.com.cn`
>
> 部署方式：本地 PowerShell 一键发布到腾讯云，服务器使用 Docker + Nginx

本文档记录 Artifex 当前生产环境的标准部署流程。日常发布只需在本地执行一条命令；脚本会自动完成检查、构建、上传、备份、部署、健康检查，并在失败时自动回滚。

## 一、当前生产环境

| 项目 | 当前值 |
|---|---|
| 腾讯云公网 IP | `82.156.244.66` |
| SSH 用户 | `ubuntu` |
| 域名 | `artifex.com.cn` |
| 服务器项目目录 | `/opt/Artifex-----` |
| Docker 容器 | `artifex-platform` |
| 应用监听地址 | `127.0.0.1:3000` |
| 数据卷 | `artifex-----_artifex-sessions` |
| 外部入口 | Nginx，端口 `80`/`443` |
| 备份目录 | `/opt/artifex-backups` |

生产链路如下：

```text
用户浏览器
    ↓ HTTPS
Nginx（80/443）
    ↓ 反向代理
Docker 容器 artifex-platform
    ↓
Node.js 服务（127.0.0.1:3000）
    ↓
Docker 持久化数据卷
```

## 二、本机和服务器要求

### 本机要求

本机需要：

- Node.js 22 和 npm
- Windows PowerShell
- Windows OpenSSH 客户端：`ssh`、`scp`
- 系统 `tar` 命令

本机**不需要**安装 Docker CLI，也**不需要**另外安装 Bash。Docker 构建和容器切换全部在腾讯云服务器上完成。

可在项目根目录检查：

```powershell
node -v
npm -v
ssh -V
scp
tar --version
```

### 服务器要求

服务器需要：

- Ubuntu
- Docker Engine 和 Docker Compose 插件
- Nginx
- SSH 服务
- 安全组开放 `22`、`80`、`443`

应用端口 `3000` 只绑定 `127.0.0.1`，不应在腾讯云安全组中向公网开放。

## 三、首次配置 SSH 免密登录

此步骤只需执行一次。已经可以从本机免密登录服务器时可跳过。

### 1. 本机生成密钥

在 PowerShell 中检查公钥：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

如果文件不存在，生成新密钥：

```powershell
ssh-keygen -t ed25519 -C "$env:USERNAME@$env:COMPUTERNAME"
```

按提示保存到默认位置。不要把私钥文件 `id_ed25519` 发给任何人，也不要上传到服务器或 Git 仓库。

### 2. 将公钥加入服务器

通过腾讯云 OrcaTerm 或已有的服务器终端登录，在服务器执行：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
printf '\n%s\n' '把本机 id_ed25519.pub 的完整一行粘贴到这里' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
chown -R ubuntu:ubuntu ~/.ssh
```

验证最后一条公钥：

```bash
tail -n 1 ~/.ssh/authorized_keys | ssh-keygen -lf -
```

### 3. 本机验证连接

```powershell
ssh ubuntu@82.156.244.66 "whoami; hostname"
```

应输出用户 `ubuntu` 和腾讯云主机名。

## 四、日常一键部署

在本地项目根目录执行：

```powershell
npm run deploy:production
```

这条命令会依次执行：

1. 检查本机命令和 SSH 连接；
2. 运行代码检查；
3. 运行自动化测试；
4. 生成生产构建；
5. 排除密钥、运行数据和本地配置后打包；
6. 生成并校验 SHA-256；
7. 上传发布包和远端部署脚本；
8. 备份服务器源码、数据卷和旧容器；
9. 在服务器构建新 Docker 镜像；
10. 切换容器并执行健康检查；
11. 校验健康接口返回的版本号；
12. 失败时自动恢复旧源码和旧容器。

也可以直接运行脚本并显式指定服务器：

```powershell
powershell -ExecutionPolicy Bypass -File deploy/production-deploy.ps1 `
  -Server 82.156.244.66 `
  -User ubuntu
```

部署脚本：

- 本机入口：`deploy/production-deploy.ps1`
- 服务器执行器：`deploy/production-remote.sh`

正常发布不需要手工上传文件、登录服务器执行 Docker 命令，也不需要修改 Nginx。

## 五、发布前注意事项

### 工作区检查

脚本会发布本机当前工作区的内容，包括尚未提交的代码。发布前建议确认：

```powershell
git status --short
git diff --check
```

### 不会上传的内容

发布包默认排除：

- `.git`
- `node_modules`
- `.env`
- `backend/data`
- `config/ark-rest-api.local.json`
- 测试报告、缓存和临时文件

因此，服务器密钥和生产数据不会被本地文件覆盖。

## 六、生产环境变量

生产环境变量保存在：

```text
/opt/Artifex-----/.env
```

部署脚本不会覆盖该文件。至少确认以下配置正确：

```env
NODE_ENV=production
PORT=3000
SESSION_SECRET=至少32位的高强度随机字符串
ENCRYPTION_KEY=至少32位且与SESSION_SECRET不同的随机字符串
ALLOWED_ORIGINS=https://artifex.com.cn
ARTIFEX_DATA_VOLUME=artifex-----_artifex-sessions
```

注意：

- 不要随意更换 `ENCRYPTION_KEY`，否则已有加密 API 凭据可能无法解密。
- 更换 `SESSION_SECRET` 会使现有登录会话失效。
- `.env` 不得提交到 Git，也不得写进更新日志或聊天记录。

只检查密钥长度而不显示内容：

```bash
cd /opt/Artifex-----
sudo awk -F= '
  /^SESSION_SECRET=/{print "SESSION_SECRET length:", length(substr($0,index($0,"=")+1))}
  /^ENCRYPTION_KEY=/{print "ENCRYPTION_KEY length:", length(substr($0,index($0,"=")+1))}
' .env
```

## 七、部署后检修

### 本机访问验证

```powershell
curl.exe -fsS https://artifex.com.cn/api/health
```

浏览器检查：

- `https://artifex.com.cn/login.html`
- `https://artifex.com.cn/modules/workflow-hub/index.html`
- `https://artifex.com.cn/modules/workflow-hub/shared.html`

### 服务器检查

```bash
sudo docker ps --filter name=artifex-platform
sudo docker logs --tail 100 artifex-platform
sudo ss -lntp | grep 3000
curl -ksS --resolve artifex.com.cn:443:127.0.0.1 \
  https://artifex.com.cn/api/health
```

容器内健康检查：

```bash
sudo docker exec artifex-platform \
  wget -qO- http://127.0.0.1:3000/api/health
```

Nginx 检查：

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
```

健康状态、容器状态、HTTPS 和关键页面均正常后，才视为发布完成。

## 八、备份与回滚

每次发布都会在服务器创建独立备份：

```text
/opt/artifex-backups/<UTC时间戳>/
```

备份通常包含：

- `app/`：发布前源码目录
- `source.tgz`：源码压缩备份
- `data.tgz`：数据卷备份
- `data-volume.txt`：数据卷名称
- `deploy-version.txt`：发布版本信息
- `rollback-container.txt`：旧容器名称

查看最近备份：

```bash
sudo ls -lah /opt/artifex-backups
sudo find /opt/artifex-backups -maxdepth 2 -type f | tail -50
```

发布失败时，远端脚本会自动恢复旧源码和旧容器，数据卷会保留，并另存一份 `data.tgz` 快照。若健康检查已经失败，不要继续反复重启或删除容器；先查看脚本输出和备份内容。

### 人工回滚

仅在自动回滚未完成时使用。先把时间戳替换为要恢复的备份目录，并确认所有路径：

```bash
BACKUP_TS=替换为备份时间戳
sudo ls -lah "/opt/artifex-backups/$BACKUP_TS"
sudo cat "/opt/artifex-backups/$BACKUP_TS/rollback-container.txt"
```

确认无误后：

```bash
BACKUP_TS=替换为备份时间戳
ROLLBACK_CONTAINER="$(sudo cat "/opt/artifex-backups/$BACKUP_TS/rollback-container.txt")"

sudo docker stop artifex-platform
sudo docker rename artifex-platform "artifex-platform-failed-$BACKUP_TS"
sudo mv /opt/Artifex----- "/opt/Artifex-failed-$BACKUP_TS"
sudo mv "/opt/artifex-backups/$BACKUP_TS/app" /opt/Artifex-----
sudo docker rename "$ROLLBACK_CONTAINER" artifex-platform
sudo docker start artifex-platform
```

回滚后重新执行“部署后检修”中的全部检查。人工回滚会切换生产容器和源码目录，必须先确认备份时间戳和旧容器名称。

## 九、常用维护命令

```bash
# 容器状态
sudo docker ps -a --filter name=artifex-platform

# 实时日志
sudo docker logs --tail 100 -f artifex-platform

# 重启应用
cd /opt/Artifex-----
sudo docker compose restart artifex

# 查看容器挂载
sudo docker inspect artifex-platform \
  --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'

# 查看磁盘和 Docker 空间
df -h
sudo docker system df

# 测试并重载 Nginx
sudo nginx -t
sudo systemctl reload nginx
```

不要执行 `docker compose down -v`，其中 `-v` 会删除持久化数据卷。

## 十、常见故障

### SSH 提示 `Permission denied (publickey)`

在腾讯云终端检查：

```bash
ls -ld ~/.ssh
ls -l ~/.ssh/authorized_keys
tail -n 1 ~/.ssh/authorized_keys
```

权限应为：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chown -R ubuntu:ubuntu ~/.ssh
```

确保 `authorized_keys` 中是一整行以 `ssh-ed25519` 或 `ssh-rsa` 开头的公钥，而不是指纹文本。

### Docker 构建下载依赖失败

项目默认使用国内镜像：

```env
NPM_REGISTRY=https://registry.npmmirror.com
ALPINE_MIRROR=https://mirrors.tencent.com/alpine
NODE_DIST_URL=https://npmmirror.com/mirrors/node
```

这些值可在服务器 `.env` 中覆盖。修改后重新运行一键部署，不要手工修改容器内文件。

### 容器启动后健康检查失败

```bash
sudo docker logs --tail 200 artifex-platform
sudo docker inspect artifex-platform \
  --format 'status={{.State.Status}} health={{if .State.Health}}{{.State.Health.Status}}{{end}}'
```

重点检查生产密钥长度、端口占用、数据卷挂载和启动日志。

### 出现数据卷已存在的提示

生产环境显式复用 `ARTIFEX_DATA_VOLUME` 指定的数据卷，这是为了保证升级时数据不丢失。用以下命令确认实际挂载：

```bash
sudo docker inspect artifex-platform \
  --format '{{range .Mounts}}{{.Name}} -> {{.Destination}}{{println}}{{end}}'
```

只要目标为 `/app/backend/data` 且卷名正确，该提示通常不影响部署。

### 网站返回 502

依次检查：

```bash
sudo docker ps -a --filter name=artifex-platform
sudo docker logs --tail 100 artifex-platform
sudo ss -lntp | grep 3000
sudo nginx -t
sudo tail -n 100 /var/log/nginx/error.log
```

## 十一、首次新服务器初始化

本节只适用于更换全新腾讯云服务器。当前服务器已经完成初始化，日常发布不要重复执行。

1. 创建或使用非 root 用户，例如 `ubuntu`；
2. 安装 Docker Engine、Docker Compose 插件和 Nginx；
3. 配置 SSH 公钥登录；
4. 配置腾讯云安全组：只向公网开放 `22`、`80`、`443`；
5. 将域名 A 记录指向服务器公网 IP；
6. 配置 Nginx 反向代理到 `127.0.0.1:3000`；
7. 申请 HTTPS 证书并启用自动续期；
8. 创建 `/opt/Artifex-----/.env`，设置生产密钥和域名；
9. 在本机执行 `npm run deploy:production`；
10. 完成健康检查、登录检查和数据持久化检查。

若服务器地址、用户、域名、项目目录或数据卷发生变化，应同步修改部署脚本参数和本文档，不能直接照用当前生产值。

## 附录：旧 PM2 手工方案

早期版本曾使用 `/var/www/artifex`、Node.js、PM2 和手工 SCP/Git 上传。当前生产环境已经改为 Docker 一键部署，旧方案不再适用，也不要混用以下操作：

- 不要在宿主机执行 `pm2 restart artifex`；
- 不要把代码上传到 `/var/www/artifex`；
- 不要在宿主机手工执行 `npm install --production`；
- 不要把环境变量写到 `/var/www/artifex/config/.env`；
- 不要绕过发布脚本直接替换正在运行的容器。

统一使用：

```powershell
npm run deploy:production
```
