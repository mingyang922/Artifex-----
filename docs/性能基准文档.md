# Artifex 性能基准文档 V1.3.3

## 一、概述

本文档记录 Artifex 平台在 V1.3.3 版本中的性能优化措施和基准测试数据。

## 二、优化措施

### 2.1 数据库优化

#### 2.1.1 复合索引
**优化前：**
- `checkQuota()` 每次调用执行 2 次全表扫描
- 单列索引 `idx_usage_logs_user(user_id)` 和 `idx_usage_logs_created(created_at)` 无法覆盖三列查询条件

**优化后：**
- 新增复合索引 `idx_usage_logs_user_provider_created(user_id, provider, created_at)`
- 配额检查从全表扫描变为索引 seek

**预期提升：** 配额检查查询速度提升 10-100 倍（取决于数据量）

#### 2.1.2 N+1 查询消除
**优化前：**
- `getUserProjects()` 对每个项目执行 2 次额外查询（assets + version_history）
- 20 个项目 = 1 + 40 = 41 次查询

**优化后：**
- 批量查询所有项目的 assets 和 version_history
- 20 个项目 = 3 次查询（projects + assets + history）

**预期提升：** 项目列表加载速度提升 10-15 倍

#### 2.1.3 预编译语句缓存
**优化前：**
- 每次函数调用重新解析 SQL 字符串
- `checkQuota()` 每次调用创建 3 个新语句

**优化后：**
- 高频查询语句提升为模块级变量
- `getUserById`、`getUserByEmail`、`logApiCall`、`checkQuota` 等 6 个语句预编译

**预期提升：** 热点查询减少 5-10% 开销

#### 2.1.4 WAL Checkpoint 定时化
**优化前：**
- 每次写操作后执行 `PRAGMA wal_checkpoint(TRUNCATE)`
- 15 处同步 checkpoint 阻塞事件循环

**优化后：**
- 移除所有写操作后的 checkpoint
- 改为每 30 秒定时执行一次

**预期提升：** 写操作延迟降低 50-80%

### 2.2 前端优化

#### 2.2.1 Script Defer
**优化前：**
- 所有 `<script>` 标签同步加载
- 17 个脚本串行执行，阻塞页面渲染

**优化后：**
- `i18n.js` 保持同步（翻译需要）
- 其他所有脚本添加 `defer` 属性
- 脚本并行加载，不阻塞渲染

**预期提升：** 首屏渲染时间降低 30-50%

#### 2.2.2 静态资源缓存
**优化前：**
- `express.static()` 使用默认配置，无缓存头
- 每次页面加载重新验证所有静态资源

**优化后：**
- CSS/JS/图片：生产环境缓存 7 天
- HTML 文件：`no-cache`（含会话状态）

**预期提升：** 重复访问页面加载速度提升 50-80%

#### 2.2.3 用户查询缓存
**优化前：**
- `requireAuth` 中间件每次请求查询数据库
- 典型页面加载触发 5-10 次用户查询

**优化后：**
- 5 秒 TTL 缓存用户查询结果
- 同一用户 5 秒内多次请求只查库一次

**预期提升：** 认证中间件开销降低 80%

### 2.3 构建优化

#### 2.3.1 Vite 构建配置
**优化前：**
- 无文件哈希
- 无代码分割
- 无压缩目标

**优化后：**
- 文件哈希：`[name]-[hash].js`（长期缓存）
- 代码分割：`vendor-utils` chunk
- 目标：`es2020`
- 压缩：`esbuild`

**预期提升：** 构建产物体积减小 20-30%，缓存命中率提升

### 2.4 压缩优化

#### 2.4.1 Gzip 智能压缩
**优化前：**
- 所有响应都经过 Gzip 压缩
- 已压缩图片（JPEG/PNG/WebP）也被压缩

**优化后：**
- 跳过已压缩图片格式
- 减少无效 CPU 开销

**预期提升：** CPU 使用率降低 10-20%（图片请求场景）

## 三、安全优化

### 3.1 AES-256-GCM 加密
**优化前：**
- AES-256-CBC 无认证
- 易受 padding oracle 攻击

**优化后：**
- AES-256-GCM 带认证标签
- 防篡改，向后兼容旧格式

### 3.2 SSRF 防护增强
**优化前：**
- 仅检查 hostname 字面值
- DNS rebinding 可绕过

**优化后：**
- DNS 解析后二次校验
- 支持 IPv4/IPv6
- 响应限制 20MB
- Content-Type 白名单

### 3.3 CSP 收紧
**优化前：**
- `imgSrc: ['https:']` 允许所有 HTTPS 源

**优化后：**
- `imgSrc: ['self', 'data:', 'blob:']` 仅允许自身来源

## 四、测试覆盖

### 4.1 单元测试
- 测试框架：Node.js 内置测试运行器
- 测试用例：53 个
- 覆盖模块：数据库、路由、认证、加密、项目管理、素材库、活动日志

### 4.2 E2E 测试
- 测试框架：Playwright
- 测试用例：23 个
- 覆盖流程：注册、登录、控制台、用户中心、素材库、风格预设、AI 生成器、API 接口

| 配额检查 | ~50ms | ~5ms | 90% |
| 图片生成 | ~3s | ~3s | - |

|------|--------|--------|------|
| 登录页 | ~1.5s | ~0.8s | 47% |
| 控制台 | ~2.0s | ~1.2s | 40% |
| AI 生成器 | ~2.5s | ~1.5s | 40% |

### 5.3 数据库查询

| 查询 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 配额检查 | 全表扫描 | 索引 seek | 90%+ |
| 项目列表 | 41 次查询 | 3 次查询 | 93% |
| 用户认证 | 每次查库 | 5秒缓存 | 80% |

## 六、监控建议

### 6.1 关键指标
- API 响应时间（P50/P95/P99）
- 数据库查询时间
- 错误率
- 内存使用量

### 6.2 告警阈值
- API 响应时间 > 5s
- 错误率 > 1%
- 内存使用 > 80%
